# Wirespec Rust Example — Petstore

A reference project demonstrating how to use [Wirespec](https://github.com/nickolasgoodman/wirespec) to generate type-safe Rust code from an OpenAPI specification. It implements both a **server** (Actix Web) and a **client** (Reqwest) for the classic Petstore API, with all endpoint types, request/response models, and (de)serialization generated by Wirespec.

## Project Structure

```
.
├── openapi/
│   └── petstore.json          # OpenAPI v2 spec (source of truth)
├── scripts/
│   ├── generate.sh            # Run Wirespec to regenerate Rust code
│   └── update.sh              # Copy Wirespec CLI binaries from a local build
├── bin/                       # Wirespec CLI binaries (per-platform)
├── src/
│   ├── lib.rs                 # Library root — re-exports generated code + runtime modules
│   ├── gen/                   # Generated code (models, endpoints, wirespec traits)
│   ├── actix.rs               # Actix Web integration (request/response conversion, register! macro)
│   ├── serialization.rs       # JSON (de)serialization via serde
│   ├── transportation.rs      # Reqwest-based HTTP transport + ClientProxy
│   ├── service.rs             # Example handler implementations (PetstoreService)
│   ├── server.rs              # Server binary — Actix Web with registered endpoints
│   └── client.rs              # Client binary — calls the Petstore API
├── tests/
│   └── integration.rs         # Integration test: spins up the server and calls it via the client
├── Cargo.toml
└── Makefile
```

## How It Works

1. **Code generation** — `scripts/generate.sh` invokes the Wirespec CLI to convert `openapi/petstore.json` into Rust source files under `target/gen/`. These files contain:
   - **Models** (`Pet`, `Order`, `Category`, etc.) with serde derives
   - **Endpoint modules** (`get_pet_by_id`, `find_pets_by_status`, etc.) with typed `Request`/`Response` structs and `Handler` traits
   - **Wirespec traits** (`Client`, `Server`, `Transportation`, `Serialization`, etc.)

2. **Server** — The `register!` macro wires generated endpoint modules to Actix Web routes. You implement the `Handler` trait for each endpoint on your service struct (`PetstoreService`), receiving typed requests and returning typed responses. The framework handles HTTP-level conversion.

3. **Client** — A `ClientProxy` combines a `Transportation` implementation (Reqwest) with a `Serialization` implementation (JSON) to satisfy the generated `Client` trait. Calling an endpoint method builds a typed request, sends it over HTTP, and deserializes the typed response.

4. **Serialization** — The `serialization.rs` module bridges Wirespec's serialization traits to serde_json for body, path, and query parameter (de)serialization.

## Prerequisites

- Rust toolchain (edition 2021+)
- Wirespec CLI binary in `bin/` for your platform (see `scripts/update.sh`)

## Usage

```sh
# Generate Rust code from the OpenAPI spec
make generate

# Build the project
make build

# Run tests (starts an Actix server and exercises the client against it)
make test

# Run the server
cargo run --bin server

# Run the client (against the public Petstore or your local server)
cargo run --bin client

# Clean build artifacts
make clean
```

## Makefile Targets

| Target     | Description                                    |
|------------|------------------------------------------------|
| `generate` | Run Wirespec code generation                   |
| `update`   | Copy Wirespec CLI binaries from a local build  |
| `build`    | `cargo build`                                  |
| `test`     | `cargo test`                                   |
| `clean`    | `cargo clean`                                  |
